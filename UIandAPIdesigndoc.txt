---

**Prompt:**

Design a **modern, clean, and responsive Leave Management web application** that seamlessly integrates with the existing application. The new screens should follow the current design system, navigation, typography, spacing, and component styles so they feel like a natural extension of the existing product. Use a **minimal color palette** (primarily neutrals with one accent color), subtle shadows, rounded corners, and clean layouts. Avoid excessive colors, gradients, or visual clutter.

### Core Features

Create the following pages and flows:

1. **Leave Dashboard**

   * Leave balance cards (Casual Leave, Sick Leave, Earned Leave, etc.)
   * Upcoming approved leaves
   * Recent leave requests with status
   * Team leave calendar preview
   * Quick action to apply for leave

2. **Apply Leave**

   * Leave type selection
   * Start date and end date picker
   * Half-day option
   * Total leave calculation
   * Reason for leave
   * Attachment upload (optional)
   * Emergency contact (optional)
   * Submit and Save as Draft actions

3. **My Leave Requests**

   * Filter by status, leave type, and date
   * Search functionality
   * Card or table view
   * Status badges (Pending, Approved, Rejected, Cancelled)
   * View request details
   * Cancel request when allowed

4. **Leave Details**

   * Complete leave information
   * Timeline showing submission, approval, rejection, or cancellation
   * Manager comments
   * Attachment preview

5. **Manager Approval**

   * Pending requests
   * Employee leave history summary
   * Team availability during requested dates
   * Approve, Reject, or Request Changes
   * Comment section
   * Bulk approval support

6. **Team Leave Calendar**

   * Monthly and weekly calendar views
   * Team member leave indicators
   * Filters by department and leave type

### Business Rules & Edge Cases

Design the UI to clearly handle these scenarios:

* Employees **cannot apply for more than 3 consecutive leave days** without manager approval.
* If the selected leave duration exceeds **3 continuous days**, display a clear informational message:

  * "Leaves exceeding 3 consecutive days require manager approval."
* Allow submission, but automatically mark the request as **Pending Manager Approval**.
* Highlight the approval requirement before submission.

Handle additional edge cases gracefully:

* Start date cannot be after end date.
* Past dates cannot be selected unless policy allows.
* Prevent overlapping leave requests.
* Prevent duplicate requests for the same dates.
* Validate sufficient leave balance before submission.
* Show warnings when leave balance is insufficient.
* Handle public holidays and weekends:

  * Clearly indicate whether they count as leave based on policy.
* Support half-day leaves.
* Allow cancellation only before approval or according to policy.
* Show informative empty states when there are no leave requests.
* Display loading, success, validation, and error states consistently.
* Support mobile-responsive layouts.

### UX Expectations

* Simple multi-step leave application flow.
* Sticky summary panel showing selected dates and total leave count.
* Inline validation with helpful messages.
* Confirmation dialog before final submission.
* Success screen after submission.
* Clear status indicators using subtle colors.
* Accessible forms with keyboard navigation and proper spacing.
* Modern tables with sorting, filtering, and pagination.
* Consistent cards, modals, date pickers, dropdowns, and badges.
* Smooth micro-interactions and subtle animations.

### Visual Design

* Modern enterprise HRMS aesthetic.
* Minimalistic interface with generous whitespace.
* Soft gray backgrounds with white content cards.
* One primary accent color for actions and status highlights.
* Rounded corners (8–12px).
* Light shadows.
* Clean icons.
* Responsive design for desktop, tablet, and mobile.
* Maintain consistency with the existing application's layout, navigation, and component library rather than introducing a new visual language.

The overall experience should feel polished, lightweight, professional, and suitable for a production-grade enterprise Leave Management System while enforcing business rules through intuitive, user-friendly interactions.
